# 现有交易数据还能支持哪些研究

这轮核对了2021年1月4日和2026年4月16日的原始盘口文件。此前抽出的每分钟第一条记录都能在原文件中复现，没有选错、漏选或多选。近期原文件确实缺少部分分钟，所以还不能用两天的五分钟模拟判断哪一年更好交易。

## 缺口发生在哪里

早期样本110只股票的26,070个分钟都有记录。近期样本142只股票应有33,654个分钟，实际只有32,694个，少960个。

缺口集中在80只股票的十二个分钟，分别是上午9点32分至9点36分，以及9点54分至10点整。剩余62只股票在这些分钟有记录。这里只定位到了缺口，还没有证明缺口由供应商、采集程序、文件处理还是市场状态造成。

另用同日有正成交额的日线股票作交叉检查。按相同代码抽样规则，两天分别有110只和142只股票，没有发现日线有交易、原始文件却完全没有连续竞价盘口的股票。这个结果只覆盖所选日期与代码子样本，也不能判断没有交易的股票本来是否应该有行情。

原始文件核查只读取证券、日期和时钟列，重建每分钟最早时间及源行号。没有再次逐字段检查全部原始十档价格与数量，也没有重新计算整个大文件的内容校验码。已有的样本成本复核记录另行保留。

## 编号对上以后还差什么

早期深市838,079条正价格、正数量成交中，买入引用有815,437条对应唯一编号，19,987条对应重复编号，2,655条没有找到。卖出方向分别为812,929、23,079和2,071条。已找到编号的最早文件时间不晚于成交，但同一时间戳内的顺序仍不知道。

早期沪市758,422条成交没有对应的委托记录。近期深市1,855,837条正价格、正数量成交按OrderID候选都能找到引用，但仍有重复编号；另有715,285条非正价格记录没有混入正常成交统计。近期沪市OrderID候选仍有大量缺失，DBOrderID候选的覆盖更低。

这些字段只作为候选编号分别检查。不同文件是否使用同一套编号、重复记录是否表示撤单或更新、不同通道间如何排序，还需要供应商说明。匹配率高不能自动证明订单簿能完整还原。

## 五分钟试算扩大到了哪里

两天共同出现的106只股票分别试算1000股、1万股和10万股，并比较立即成交、每分钟等量分批和限价等待。每一天只读取当天9点30分至9点35分的报价，首条报价不得晚于开盘一分钟。早期有一只股票在窗口内出现无效盘口，整条路径排除并记录；近期没有这类排除。共得到3798组试算。

早期105只纳入股票都有一分钟内的结束报价，近期106只中只有43只具备。这会直接影响分批完成率和成本能否算出。费用、排队、自身订单对行情的影响仍未加入，挂单按后续快照刷新也只是模拟假设。

独立逐档算法重新计算了全部3798组路径、20,867笔档位成交以及36个汇总格。日期、现金、数量、结束报价年龄和成本核算一致。这证明所声明假设下的计算能复现，不证明实盘能按这些价格成交。

## 回测按0.4%收费怎样理解

0.4%等于40基点。若买入和卖出每一侧都收0.4%，每天买卖各占净值60%、一年250天的线性支出比例就是120%。若一买一卖合计0.4%且两侧均分，比例是60%。这是资金规模固定时累加支出的算术情景，不是实际净值损失。

40基点高于本样本10万元订单的静态成本中位数，适合加入压力测试。它仍不能保证覆盖挂单不足的大订单、等待和未成交损失。如果0.4%已经表示全部交易费用，就不能再重复加佣金或相同的滑点。

[中国A股因子模型研究](https://doi.org/10.1016/j.irfa.2023.102975)曾采用37基点单边成本，依据来自2009至2016年的价差研究。这个历史研究参数可以解释为什么有人使用较高费用假设，不能直接当成当前所有股票的真实费用。

## 下一步怎样推进

先解释近期这80只股票为何在相同分钟缺报价，核对其他本地副本、采集记录及供应商覆盖说明，再尝试修补。修补前把这些缺口保留在比较结果里。

逐笔事件需要取得或找到本地已有的字段字典、撤单关系和跨文件交易所顺序。真实滑点仍需要实际订单、成交及费用文件，本轮没有把盘口试算升级成实盘校准。

## 复现

在包含duckdb、pandas、pyarrow和quant-platform的项目环境中运行。输入为此前扩展研究的私有样本清单及保存数据，输出必须使用新的仓库外目录。

```bash
PYTHONPATH=src python scripts/run_execution_data_fitness.py \
  --spec "$EXECUTION_EXPANSION_SPEC" \
  --saved "$EXECUTION_EXPANSION_SAVED" \
  --output "$NEW_EXTERNAL_RUN"
python -m pytest tests/studies/test_execution_cost_fitness.py -q
```

公开JSON只保留汇总数量、分组结果及研究范围。原始路径、证券编号、逐笔成交和私有输入清单不公开。
