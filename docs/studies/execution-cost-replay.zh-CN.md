# 深市回放质量门槛与盘口路径执行对照

[English](execution-cost-replay.md)

早期深市订单引用已核查，但完整事件回放仍未通过门槛：订单类型、撤单含义和跨流交易所顺序尚未验证。因此，没有给出订单簿重建误差，也没有把盘口路径模拟称为真实滑点或因果冲击。

在2021-01-04的共同样本中，深市838,079条成交的买卖订单引用候选匹配率分别为99.6832%和99.7529%。已找到的引用订单，其首次出现时间均未晚于对应成交。订单和成交流有441,806个相同证券／时间戳组合；只有时间排序不能确定这些并列事件的先后。数字事件类型仍缺少供应商字典，重复订单编号可能是更新或撤单，不被随意删除。

## 已完成的有界对照

按代码顺序选择最前12只深市证券，使用1万股假想订单、五分钟窗口和100万元买入现金上限。买卖分别对照立即吃单、固定时钟等量执行、限价等待。分时订单在0、60、120、180、240秒预先释放数量，不以未来快照数量决定计划。

通用撮合复用quant-platform的`ticknet.simulator.matching.LimitOrderBook`。按每一档调用提供方，再汇总实际匹配价乘数量，避免提供方多档返回值以最后价格代表整笔成交而导致金额错误。每个快照时点的数量和买入现金均受约束；不足的部分继续保留。

本对照假设后续快照可重新提供可见深度，且不受假想订单影响。这不是证实的盘口恢复过程。限价等待只模拟价格交叉后的吃单，不推断被动挂单能否排到；额外被动成交的保守界为零、乐观界为全部剩余数量，这一宽界不能给出成交概率或现金结果。

参与率约束模式暂不可用：已存`TotalVolume`没有经过核验的区间成交量、重置和竞价口径。需要先验证数量单位、时钟和可用的滞后成交量基线，不能借用未来区间成交量。

每种方式各有12条买卖路径。完整成交数量分别为：立即吃单11／12，等量执行12／12，限价等待8／6。这些是选定路径、盘口刷新假设下的完成诊断，不能判断实盘算法谁更好；未包含税费、整手、隐藏流动性或自身冲击。

路径成本核算已采用到达时中间价，并在相同固定窗口结束时保留未成交机会成本。结束报价最大允许过期60秒，只用于事后评价，不影响下单数量、限价或计划；过期或无有效双边报价的成本留空。买卖符号、现金与数量守恒需逐路径复核。同时记录完成时长。这同样是反事实成本，不是实盘校准；负成本可能反映样本价格变化。

## 复现与核查

```bash
PYTHONPATH=src python scripts/run_execution_cost_replay.py \
  --saved "$DATA_ROOT/quant/quant-market-research/ashare_execution_costs/expansion-20261012/l2-run-v1" \
  --output "$NEW_EXTERNAL_RUN"
python -m pytest tests/studies/test_execution_cost_replay.py -q
```

需要包含已安装quant-platform的环境。输出目录必须为空或不存在；源文件、提供方与研究代码的校验码、按证券引用统计及逐路径成交保存在私有记录。`replay.proposed.json`仅包含固定字段的聚合提案，必须审查后才能发布，不包含证券编号或机器路径。

最早的试跑曾按快照数量安排分时订单，随后已用预定时钟计划替换，并加入未来记录变化不能改变已发生成交的回归测试。各次试跑及确切生产代码保留在仓库外，发布仅使用最终审查版本。

要进入完整回放，还需供应商订单／方向／撤单字典、跨流顺序来源和竞价到连续交易的初始簿证据。验证后才能使用共享提供方重建，并对照快照检查最优价、各档数量、交叉簿与撤单守恒误差。
