# Research extensions: evidence required before a run

[简体中文](literature-intake-20261128.zh-CN.md)

The first deliverable is a source-bound method and an honest evidence status.
The source material supplied in conversation does not independently verify most
original papers. No paper's headline Sharpe is a replication target or release
criterion. Existing studies, their frozen protocols and negative results remain
authoritative. This intake does not authorize a new public performance claim.

Execution evidence must retain unfilled/censored orders. Snapshot depth is not
proof of true queue position. When order-level reconstruction is impossible,
report a bounded assumption sensitivity rather than a calibrated queue model.
Implementation of generic fills/accounting belongs to Engine; this repository
owns the market-specific empirical method. Data publishes normalized assets;
Platform consumes stable public provider APIs.

The existing execution follow-up already records a missed prospective archive
start. Do not reconstruct it as unseen. A replacement protocol needs an actual
new pre-session registration and an operational daily archive before observing
outcomes. This document starts neither an archive job nor a new holdout.

## Execution order

1. Audit input metadata and source availability; retain unknowns and blockers.
2. Freeze the experiment, benchmark, selection family, data versions and limits.
3. Run synthetic contract tests, then a separate reproducibility check using only
   eligible existing development data. Register each outcome access privately.
4. Review derived evidence, costs, capacity and uncertainty before public export.

Full private evidence and generated outputs remain outside source repositories.
Public summaries require explicit field allowlists and reviewed publication
manifests; do not copy private research locators or security-level signals here.
