# BMLL 美股流动性试验

[English](README.md)

本试验检查事件级数据能否改善小微盘执行研究，观察报价价差和年龄、成交相对报价的位置，以及固定比较窗口里的变化。换仓频率只用于成本情景计算，当前不据此证明小微盘溢价、策略可交易性或账户容量。

## 样本与解释范围

共享数据包含证券参考表、全市场最优买卖报价 NBBO 和 Trades Plus。参考字段标成 L3 不代表开放了完整订单消息或多档深度。最优档展示数量不能保证成交，本试验也不能模拟排队和深层吃单。

配置固定了十二个候选证券，其中两只是 ETF 参照，以及三月的两个基线日期和四月的五个比较日期。候选沿用早期探索名单，属于回顾性选样，不是四月之前按市值规则形成的完整股票池。历史特征快照提供首个基线日的滞后市值与 ADV20，即过去二十个交易日的平均成交额，但尚未认证原始发布时间可得。ETF 与普通股票分开统计，不能把九月分组直接用于三月。

证券参考表按日期和上市标识连接，汇总前检查映射唯一性。SIP 汇总记录的 `is_primary` 不一定为真。`is_alive` 只描述共享参考快照里的身份状态，不能解决幸存者偏差或历史修订。正式研究需要独立核实历史资格和公司行动。

## 四个调查方向

| 问题 | 本轮能提供什么 | 仍需补充什么 |
|---|---|---|
| 跨过买卖价差要付多少成本 | 时间加权 NBBO 与成交时点有效价差诊断 | 报价新鲜程度、费用、实际下单规则和执行验证 |
| 压力窗口里什么发生了变化 | 同一证券前后比较价差、报价年龄和买一档金额 | 更多时段、匹配对照和独立事件选择 |
| 小公司之间有哪些区别 | 滞后市值、成交额及观测到的价格和活跃度 | 带披露日期的基本面、历史身份、融资摊薄和退市记录 |
| 降低换仓频率能节省多少 | 不同持有间隔下的明确成本情景 | 样本外收益信号、持仓和真实换手 |

四月日期是预设比较窗口，不构成事件因果归因。先计算每只证券的日均指标，再跨证券汇总。组中位数之比和逐证券比值的中位数回答不同问题，变化方向也可能不同。

## 指标与检查

报价窗口分别为纽约时间 09:30 至 10:00、11:00 至 11:30 和 15:30 至 16:00，左闭右开。UTC 事件时间按 `America/New_York` 转换，以保留夏令时规则。每个窗口接续之前最后一条报价，并在两端截断持续时间。分别核对总覆盖、有效且未交叉的报价，以及数量字段覆盖。六十秒只是一种报价年龄诊断阈值，不是交易所规定的失效时间。旧报价可能仍有效，新报价也不保证能成交，市场状态标签本身不能认证可交易。

成交统计覆盖执行日期与公布日期分区相同、纽约时间 09:30 至 16:00 的连续交易。成交的开盘、盘中和收盘分组比报价窗口更宽，不能直接当成同一观察区间。跨日延迟报告被排除，当前没有重建完整经济成交账本。成交量诊断保留撤销记录的负数量，成本统计排除同一天内出现撤销或修订的成交编号组。跨日更正和数据源身份歧义仍未解决，事件行数不能直接称为独立经济成交笔数。

完整报价价差为 `(卖价－买价)÷中间价×10000` 基点。带方向的有效价差为 `2×方向×(成交价－中间价)÷中间价×10000`，主动方向代码 1 记为 +1，代码 2 记为 −1。代码 0 为未知，不参与带方向指标，并单独报告占比。成交价与中间价的绝对距离另作诊断。主动成交后的价格变化为 `方向×(未来中间价－成交价)÷当前中间价×10000`，正数有利于主动成交方。未来中间价只能评价结果，不可用于当时的特征，缺失期限使用各自的有效分母。

成本情景为 `完整价差基点÷10000×252÷持有交易日数×替换比例`，假设一次完整买卖承担一个完整价差。它是算术成本门槛，不是实际亏损估计或预测。计算没有包含冲击、费用和收益信号，报价价差也不一定等于投资者实际支付的价差。

## 私有复现

使用已经配置的 Databricks CLI 身份，脚本不接收 token。用 `uv sync --locked --extra duckdb --extra dev` 安装开发环境。

```sh
python scripts/generate_bmll_pilot_sql.py
# BMLL_WAREHOUSE_ID 为已有仓库标识，BMLL_RUN_ROOT 为新的私有数据目录。
uv run python scripts/run_bmll_query.py --warehouse-id "$BMLL_WAREHOUSE_ID" --sql sql/bmll/reference.sql --output-dir "$BMLL_RUN_ROOT"
uv run python scripts/run_bmll_query.py --warehouse-id "$BMLL_WAREHOUSE_ID" --sql sql/bmll/trades.sql --output-dir "$BMLL_RUN_ROOT"
uv run python scripts/run_bmll_query.py --warehouse-id "$BMLL_WAREHOUSE_ID" --sql sql/bmll/quotes.sql --output-dir "$BMLL_RUN_ROOT"
# BMLL_FEATURES 指向原流动性研究所用的历史特征 Parquet。
PYTHONPATH=src uv run python scripts/summarize_bmll_pilot.py --input-dir "$BMLL_RUN_ROOT" --features "$BMLL_FEATURES" --output-dir "$BMLL_RUN_ROOT/analysis"
```

查询只读，并限定证券和日期，保存 SQL、语句标识与结果。解释连接后的结果之前，要核实参考映射唯一性。结果解析器拒绝部分或截断结果，扩大样本后可能需要明确取回所有结果块。脚本不创建计算资源或修改权限，但查询可能启动所选的已有仓库，并产生计算用量。

供应商派生的逐证券观测和报告留在 Git 之外，不假定拥有任意再发布权限。小微盘公开网站可链接审核后的方法结论，新的数值发布需要单独检查授权和汇总范围。

字段依据为 [BMLL Trades Plus 说明](https://www.bmlltech.com/files/documents/BMLL-Trades-Plus.pdf)和[数据覆盖说明](https://www.bmlltech.com/market-data-coverage)。实际可用字段以共享表结构为准，不能仅凭最新 PDF 假定所有字段都已开放。
