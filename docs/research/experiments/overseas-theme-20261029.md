# Overseas semiconductor theme: method ready, historical inputs missing

Later on 2026-10-29, bounded provider retrieval and three experiments completed. See the [source audit and actual results](overseas-theme-source-results-20261029.md). The inventory below preserves the earlier state before those requests.

No new empirical semiconductor-theme conclusion is available. Read-only inventory of the owner project's external data directory found previous broad-index overseas lead-lag derived results but no identifiable SOX, SMH, SOXX, NVDA or TSM historical CSV/parquet input, nor a reviewed theme manifest. Derived broad-index forecasts cannot substitute for semiconductor history. No raw provider was queried and no shared publication pointer was changed.

The experiment extends the existing retrospective methodology, leaving frozen forward v1 unchanged. For SW semiconductors it evaluates the opening gap and open-to-close return; for 512480 it evaluates adjusted open to next tradable adjusted open. The baseline contains domestic lags, momentum, volatility, CSI controls, FX and SPX. Each annual expanding fold fits semiconductor-return intercept and SPX beta in training rows only, then adds the resulting residual to baseline OLS. Training labels must end before the first test decision. Inputs use the existing conservative close-plus-one-hour assumptions at 08:45 Asia/Shanghai, with zero and one A-share observation delays. Ten-observation paired block uncertainty, annual summaries and ETF 0/5/10/20/40 bp round-trip sensitivity preserve negative outcomes. Residualization is a linear reparameterization with SPX already included: it does not create new independent information or establish causality.

The authoritative data-platform contract and catalog were also inspected read-only: `docs/contracts.md`, `metadata/dataset_registry.csv` (dated 2026-10-29), and `metadata/current_assets/*.json`. The registry describes current A-share assets; no SOX/SMH/SOXX/NVDA/TSM/global-US match appeared in those catalog/contract records. A filename inventory of the owner platform assets, metadata and published trees likewise found no matching theme history. This is an inventory of available reviewed assets, not proof that no unregistered archive exists.

The runner requires a clean committed checkout, including no untracked source files, and verifies that revision again before exporting. Run from that checkout:

```bash
python -m market_research.studies.overseas_leadlag.theme \
  --manifest /external/reviewed-theme-inputs.json \
  --output /external/task-results/new-run
```

The JSON manifest requires `reviewed: true`, `study_id`, `index_inputs`, `extra_inputs`, `theme_input`, optional `start_year` (2020 default), and `sources`. Each source ID maps to `{ "path": "/external/file.csv", "url": "https://provider/source", "sha256": "64 lowercase hex characters" }`. Paths are private manifest fields and excluded from publication. Every consumed file must have a matching hash. The runner hashes the manifest bytes and rechecks the manifest and all inputs before writing evidence; the manifest digest remains in external diagnostics. Input CSVs follow the existing `trade_date` YYYYMMDD daily-bar contract. Theme input must be a reviewed US semiconductor close series with `close`; its regular close is interpreted in America/New_York including DST.

Required files: index inputs `000300_sh_tushare_daily.csv`, `801081_si_sw_daily.csv`, `spx_tushare_daily.csv`, `hsi_tushare_daily.csv`, `n225_tushare_daily.csv`, `ks11_tushare_daily.csv`; extra inputs `usdcnh_fxcm_fx_daily.csv`, `usdjpy_fxcm_fx_daily.csv`, `eurusd_fxcm_fx_daily.csv`, plus `510300_sh_fund_daily.csv`, `510300_sh_fund_adj.csv`, `512480_sh_fund_daily.csv`, `512480_sh_fund_adj.csv`. The current loader also audits 510300 even though this study reports only semiconductor targets. Most importantly, the reviewed theme history, documented provenance URL, hashes and reviewed manifest are missing. Existing derived result archives alone are insufficient to reconstruct these inputs.

Outputs remain external: daily predictions, fold bounds, timing audits, full research diagnostics, and the allowlisted `overseas_theme_evidence.v1.json` publication candidate. The versioned [JSON Schema](../../contracts/overseas_theme_evidence.v1.schema.json) defines the publication shape; the Python validator additionally checks source/hash equality, evidence linkage, finite ordered intervals, UTC and sample-date order. Comparisons carry stable evidence IDs tied to source IDs; `baseline` and `augmented` are model identifiers. Publication requires full source Git SHA, input SHA256 values and nonempty limitations. Consumers must treat `retrospective_exploratory` and `historical_pit_certified: false` as substantive limitations. A sample ending recently is still retrospective evidence, never today's forecast.

No untouched holdout, historical retrieval vintage, historical universe selection, fill/capacity proof, or multiplicity-adjusted inference is claimed. The runner does not download data or deploy models. Review the candidate evidence before selecting it for any downstream publication.
