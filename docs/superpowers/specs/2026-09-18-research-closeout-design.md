# Quant Research Closeout Design

## Goal

收口公开量化研究仓库的算法状态、数据新鲜度展示和网站发布验证，使读者能区分已验证结果、探索性结果、数据待补状态和快照生成时间。

## Scope

本轮包含三个相互依赖但可独立验收的子项目：

1. 研究状态与算法边界：为现有微盘、低换手和 Barra 研究补充可执行的验证入口、回归契约和明确的未完成事项；不在缺少仓库外原始数据时生成伪造结果。
2. 新鲜度与网页展示：统一公开快照元数据，网页展示快照生成时间、各数据集 as-of、覆盖区间、来源和质量状态。
3. 发布与重构收尾：修正本地静态校验的构建顺序，更新过期计划文档，按需降低或记录前端包体积警告。

## Architecture

公开数据文件继续是审核后的派生快照，原始行情和完整研究运行结果仍留在仓库外。新增统一 provenance manifest，由快照构建脚本生成并由网页读取；专题页面通过共享组件展示元数据，不在各页面重复硬编码日期。算法相关改动优先增加 Python 回归测试和文档门禁，不能访问原始数据的任务只提供重算命令、输入契约和 pending 状态。

## Data Contract

每个公开快照至少包含 `generated_at`、`as_of` 或明确的 `coverage_start`/`coverage_end`、`source`、`quality_status` 和 `caveats`。`generated_at` 表示派生文件生成时间；`as_of` 表示数据实际截至时间；两者不可互换。缺失日期显示“日期待补”，不能显示“最新”。

## Web Contract

首页和每个专题页必须展示对应快照的 freshness summary。跨市场数据按市场分别展示 as-of；不完整、待刷新和探索性数据必须保留状态标签。指数和 ETF 页面不得继续使用无具体日期的“已发布的历史数据”作为唯一时间说明。

## Validation

必须通过 Python 测试、Ruff、Web 测试、Astro 构建、MkDocs 严格构建、静态站点校验和现有浏览器冒烟路径（若环境具备 Chromium）。构建顺序必须先生成 `web/dist`、再生成 `web/dist/docs`，并创建 `.nojekyll` 后运行静态校验。

## Non-goals

本轮不把探索性结果升级为生产策略，不修改仓库外原始数据，不把历史 Barra 结果包装成商业 Barra 复刻，不在缺少外部输入时重算并发布新的收益数字。
