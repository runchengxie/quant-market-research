# 统一研究网站：导航、阅读与交互设计规格

日期：2026-09-19

状态：待用户审阅；整体方向已获同意，尚未编写实施计划或修改产品代码。

代码基线：`af5b8b9cf8d7075325b1a0e9617465956bded1d4`（PR #99、#100 已合并）。

## 1. 已认可的目标与边界

用户希望网站更加美观、易懂、大气、直观、互动性好，尤其解决研究图表、说明文档和不同专题看起来像多个网站的问题。已认可的方向是：研究阅读为主、交互探索为辅；统一站点框架与导航；在研究主题内贯通图表、定义、方法和证据限制。

主要使用者按希望理解、比较和复核研究的中文读者设计，兼顾网站维护者。成功意味着读者能找到主题、理解图表、查到方法，再返回原来的分析上下文，不必学习第二套导航。

本次包括：

- 所有现有公开研究页面、首页、404 页面，以及现有 7 份公开说明。
- 全站导航、主题切换、阅读排版、图表与表格规范、静态搜索。
- 因子定义与来源的版本化展示，以及网页和说明之间的内容一致性。
- 原 URL、章节链接、因子选择链接和既有交互的兼容性。
- 对应构建、公开边界、行为测试和实际视觉验收。

本次不包括：更换 Python 研究引擎，改写历史收益，重建完整 19 因子历史，新增交易功能、账户、数据库或 CMS。历史来源、PIT 和 Quality 运行记录不足的问题仍如实保留。不得借迁移公开内部运行手册、原始行情、私有策略或凭证。

## 2. 现状与架构选择

当前 Astro 页面共用 `SiteLayout.astro`，但普通专题采用暖色报告样式，Barra 使用 `.research-workbench` 的独立冷灰蓝覆盖。说明站由 MkDocs/Bootstrap 构建到同一产物目录中的 `/docs/`，有不同导航、目录和主题控制。

`SiteHeader.astro` 的顶层入口直接列研究主题，说明入口主要在页脚。文档导航另列“研究说明／因子研究”。`build-pages.mjs` 和 Pages 工作流先生成 Astro，再生成 MkDocs；当前校验还要求 Bootstrap 等说明站专属资源存在。

选用上一轮已推荐的方案：公开说明由现有 Astro 统一渲染，正文继续保留为 Markdown。只给 MkDocs 换色的方案改动较少，但仍维护两套模板和阅读路径，不作为最终架构。无需更换现有 Astro、React 或 ECharts，也不为迁移引入整站文档框架。

本规格取代旧 `2026-09-18-astro-first-research-site-design.md` 中“本次不迁移 MkDocs、不改变视觉设计”的范围限制；继续遵守 Astro 负责路由和正文、React 负责交互的原则。

## 4. 三种页面模板

### 4.1 总览与目录

首页采用简洁品牌介绍、一句研究定位、少量有数据依据的发现、研究入口。大标题只出现一次；“探索性研究”与重要限制紧邻结论。主题目录、方法目录、数据目录复用同一页面框架，不另设品牌样式。

### 4.2 研究专题

阅读顺序是：研究问题与简要发现 → 必要日期／口径 → 核心图表 → 如何读图 → 定义和方法 → 数据与局限 → 相关研究。

主图、选择器、适用样本和单位放在一个视觉组中，辅助图表与明细后置。Barra 保留图表优先和 19 因子选择，下方定义、公式、Quality 诊断仍随选择变化。其他专题保留各自有意义的图表，不机械套用 Barra 控件。

已知的短样本、不同版本、非可交易收益及完整案例筛选限制直接可见。完整公式推导、字段表和补充诊断可展开，但不能把影响解释的核心限制藏起来。

### 4.3 方法文章

采用同一页头、面包屑、颜色、字体、页脚和主题控制。正文窄栏、图表按需要扩展；长文章显示章节目录，并提供明确的“回到相关图表”链接。

文章结构以读者问题为顺序：研究对象、如何计算、如何解释、适用范围、来源／版本、相关图表。代码和详表不挤占开头。每页仅一个正文 `h1`；品牌使用链接而非全站重复 `h1`。

## 5. 统一视觉与交互规则

- 基调为接近白色的中性背景、深墨色正文、克制的蓝色强调；深色模式提供成套语义颜色。移除按某个专题重定义全站色板的例外。
- 默认使用可靠的中文无衬线系统字体栈；标题和正文同族，数字用等宽数字，代码才使用等宽字体。首屏不依赖远程字体服务。
- 正文默认 16px，辅助说明通常不低于 13px；主题标题约 28–40px。图表标签桌面不低于 12px，手机不靠缩小字号容纳全部信息。
- 页面最大宽度约 1240px，文章正文最大约 46rem；小屏保留 16–20px 页边距。间距使用同一套 4/8/12/16/24/32/48px 等级。
- 用标题、留白和轻分隔组织正文；卡片主要包围图表、关键指标和真正独立的交互模块，避免卡片套卡片。
- 页头紧凑且可吸顶；章节导航需设置正确的滚动定位偏移。手机折叠导航有明确展开状态、焦点处理和关闭方式，不依赖悬停。
- 所有按钮、链接、选择器、表格、警告和空状态使用共享组件规范。交互反馈要有文字／形状辅助，不能只靠颜色。
- 浅色／深色／跟随系统共用现有主题偏好键；切换研究页与说明页不丢选择，首次渲染避免闪烁。

视觉参数是本次统一基线；实际验收允许为可读性微调，但不得重新演变成专题各自一套主题。

## 6. 图表与表格合约

共享图表容器负责标题、单位、样本范围、必要限制、图例、图表、读图说明、数值表入口和方法链接。ECharts 图表和现有报告式静态图都遵守这套外层规范；没有交互需求的简单图不必为了统一强行改成 Canvas。

图形规范统一坐标字号、网格、提示框、图例位置、日期／百分比格式和移动端行为。收益正负保留零线、符号或标签；主序列、参照序列、正负值与验证状态使用各自明确的语义颜色。数据有适合比较的共同范围才并列比较，不跨样本暗示优劣。

动态图保持现有筛选、URL 因子状态、缩放等有用能力；静态图不伪装成可点击控件。交互表格明确排序、当前范围、总数和分页。单位、缺失与零严格区分；可观察部分收益不能作为完整组合收益显示。

所有图都有相邻文字说明或可访问数值；键盘不操作 Canvas 也能选择主题、因子和查看表格。可选数据失败只影响相应模块，并提供重试；无数据与加载失败分别显示。

## 7. 内容与版本：同源不等于同一模型

建立公开内容注册表，统一维护专题 ID、页面路径、标题、简介、方法关联、数据来源引用和可搜索别名。导航、目录、面包屑、相关链接和搜索索引从注册表派生。Markdown 仍是长文唯一正文源，不复制一份 JSX 文章。

因子内容按“模型／实现来源 + 版本 + 因子 ID”区分至少三类记录：

1. 历史运行包中的收益序列及其已知方向、覆盖与 provenance；原生成公式未确认时保留未知。
2. 已核查的现行生成实现，目前依据 `quant-research` 的 `b4317aa...`；核查源码不代表它就是历史生成版本。
3. 本仓 `factor-descriptors.yml` 描述的核心代理字典及其版本；不能与前两类仅凭同名合并。

网页详情、方法文章中的结构化定义、搜索摘要和版本说明都引用同一组带版本记录。保留已有机器可读字段的消费者契约；可增加版本关联，不未经验证改变算法意义。

Quality 是必须覆盖的内容一致性案例：核查实现使用按公告排序的 8 个财务观测、至少 4 个，不保证连续季度；文档中连续 8 季度的说法必须明确归属于哪个定义及验证程度。先核实来源再修正文案，不能全局替换文字后声称两个实现相同。组件列缺失与个股组件值缺失的处理分别描述。

同样核对规模方向、Beta 窗口、流动性与交易流字段、收益单位、样本日期。矛盾或缺证据的定义不得自动标记为已验证。历史收益、Quality 快照、市值 v2 派生数据保持不变；本次不运行快照发布器或研究重算来完成视觉迁移。

“数据与版本”只聚合现有已公开 manifest 和审计字段，不扫描原始数据目录。展示生成时间、数据截止、覆盖和方法版本的区别；不得把网页发布时间当作数据更新日期。阶段性状态报告保留原来的日期，不能把旧状态冒充实时状态。

## 8. 静态内容架构与发布边界

复用现有 Astro。页面框架管理全局导航、主题、元信息和宽度；专题／文章布局管理阅读结构；React Islands 仅承载图表、搜索、筛选和表格状态。

公开 Markdown 通过 Astro 构建期内容机制加载。公开注册表的明确文件列表是准入边界：不得通过加载整个 `docs/**` 再在页面端隐藏内容来实现。未列入的规格、计划、运行手册、内部记录既不产出页面，也不进入搜索、站点地图或浏览器 bundle。

因子结构化片段由共享记录渲染；其所在 Markdown 保留背景和解释，不再手抄第二份公式表。普通 Markdown 相对链接按明确的页面映射转换；章节目录和兼容锚点由同一次内容处理产生。

最终 Pages 产物由 Astro 单一所有者生成。MkDocs 如保留作维护预览，输出到 Git 忽略的 `.build/mkdocs-reference/`，不再写 `web/dist/docs`，也不发布预览产物。保留仓库需要的 MkDocs 严格校验，更新相关操作说明；公开 CI 必须验证 Astro 生成的真实说明页，而不是继续以 Bootstrap 资源存在作为通过条件。

不得删除旧门禁却不提供替代：新门禁继续检查全部公开路由、静态正文、数据链接、资源、UTF-8/NUL、隐私边界、正文锚点和文档互链。迁移公开说明的路由和发布构建应在同一可验证发布单元中切换，防止后一构建阶段覆盖前一阶段。

保留 PR #100 的 React Web Streams 渲染修复。若改动渲染路径，必须重新验证原始 HTML、客户端挂载、分页 ARIA ID 和异常处理；不能仅验证浏览器最终画面。

## 9. 搜索、错误状态与性能

搜索采用构建时生成的小型公开索引和轻量前端匹配。索引包含专题、公开文章的标题／章节／正文，以及因子名称和别名；不包含个股原始数据、内部文件或完整快照数组。支持中文片段和英文 ID 查询，结果标明主题和内容类别，并链接到精确章节。

通过标准搜索入口和 `/search/?q=` 使用；结果为空、索引加载失败和重试均有明确状态。没有 JavaScript 时仍能通过目录浏览全部公开内容。查询不发送到外部搜索服务，不增加分析追踪。

首页和方法页不因为统一框架而加载 ECharts 或市值大 CSV。搜索索引仅在搜索页面／实际发起搜索后请求；全文索引目标不超过 250 KiB 未压缩，超出需删去重复片段或按需拆分。保留市值诊断展开后加载和表格分页，禁止重新渲染数万行完整 DOM。

构建时缺失必需公开文件、重复路由／ID、无法解析的必要元信息或越界引用应失败。运行时缺失数据不显示零值、过期结论或“已完成”占位。历史 formula 未核实属于正常证据状态，不是程序异常。

## 10. 验收标准

### 10.1 信息架构与兼容性

- 所有研究页、7 份说明和 404 使用相同页头、页脚、主题控件与一级导航。
- 研究目录覆盖全部 8 个现有研究 URL；研究与相关方法双向可达，无同站“另一个网站”的导航切换。
- 全部旧 URL、已记录旧锚点、首页 hash 跳转、合法与非法 `?factor=` 行为有自动测试。
- 带因子状态进入定义页再返回，仍保留所选因子；浏览器前进／后退行为符合 URL 状态。

### 10.2 内容与公开边界

- 因子定义在专题和文章引用同一版本记录；19 个历史因子保持可达，Quality 四子项和版本区别完整呈现。
- 公开白名单与实际页面／搜索索引逐项对应；测试用内部文档样例证明它不会出现在产物中。
- 既有公开数值快照保持字节不变；若核查发现必须改数据，单独报告并另立算法／数据修订范围，不夹在此次迁移中。
- 保留历史来源未确认、Quality 记录未恢复、市值完整案例选择限制等已知边界。

### 10.3 行为、可访问性与视觉

- 320、390、768、1280、1440px 检查页面无全局横向溢出；大表只在自身容器横向滚动。
- 浅色、深色、跟随系统下，正文对比度至少 4.5:1；大字号及关键控件至少 3:1。键盘焦点可见，菜单、目录、搜索、筛选和分页可操作。
- 主体语言、单一正文 `h1`、标题层级、跳至正文链接、ARIA 状态和分页关联 ID 正确。
- 对首页、Barra、低换手、微盘、长方法文章分别实看桌面／手机和明暗截图；另巡检全部路由。只通过截图文件生成或断言不算完成视觉验收。
- 在浏览器测试中验证导航往返、主题保持、搜索、19 因子联动、无效链接、数据失败与重试、分页和按需加载。

### 10.4 工程与发布

- Python、前端单元测试、Astro check/build、MkDocs 参考严格校验、静态站点检查、浏览器测试和 `git diff --check` 通过；按新架构更新真实行为断言，不为消除失败而降低门禁。
- 基线功能测试数参考上一轮的 Python 204、前端 91、浏览器 25；这些是上一轮记录，不是本规格阶段的新测试结果。实施时以实际新增后的完整结果交付。
- 公共构建只由 Astro 写入 `/docs/`；不得有第二生成器覆盖它。记录首屏资源和按需数据请求，避免整站引入新的大依赖。
- 独立审查、PR 必需检查和部署完成后再清理任务分支／工作树；主检出干净时仅快进同步。

## 11. 发布组织与当前审批状态
