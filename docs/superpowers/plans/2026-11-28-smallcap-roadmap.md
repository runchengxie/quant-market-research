# Small-cap research roadmap and target-support exploration

**Goal:** Turn the agreed P0–P3 research directions into a complete dependency-aware checklist and advance matched low-turnover target construction with an external, reproducible diagnostic.

**Architecture:** quant-market-research owns the task registry, diagnostic code and reviewed aggregate results. A Study in Small Caps publishes a source-pinned copy with bilingual task details and links to the evidence. The page reports deliverable status, never a percentage of scientific certainty.

**Execution:** Native implementation in this session, as requested by the user. Existing reports and frozen observations remain unchanged.

## Work

- [ ] Add a bilingual registry with stable task IDs, priority, status, dependencies, acceptance, next action, evidence and repository ownership. Validate unique IDs, DAG structure, status/evidence integrity and that ready/done tasks have satisfied prerequisites.
- [ ] Add regression tests, then a three-arm target-support diagnostic over archived formation panels. Form the smallest fifth before any future-return filter; preserve signal missingness. Compare common-support benchmark, high-turnover exclusion and low-turnover selection. Report support, count, exposures, target changes and missing industry; do not calculate execution or net returns.
- [ ] Run the retained panel outside Git, fingerprint inputs/outputs and independently reconcile weights and consequential summaries. Inspect named historical window-replay records where available; distinguish identified files from recovered generating inputs.
- [ ] Populate the checklist with evidence earned by completed work and explicit remaining gates; publish reciprocal English/Chinese records.
- [ ] Validate/merge the provider, then publish a source-pinned bilingual task/evidence map in the small-cap site with priority/status filters, deep links and a readable no-JavaScript view.
- [ ] Validate both final versions, merge and verify deployment; retire only this task's worktrees/branches. Retain results, lock identities and REPRODUCE.md.

## Review focus

Missing scores must not turn into zero; common support must be defined without future outcomes; changing target weights is not realized turnover; uncertainty/missing factors must survive aggregation; a waiting task must not become ready solely because a description exists. Tests pin these boundaries.

No new environment installation, downloads or production jobs. Existing dependencies are reused. New bytecode/pytest/Ruff scratch belongs only to this task worktree and is disposable at verified worktree retirement; generated site/cache output is routed to task data directories. Logs, source identities and diagnostic outputs are retained, not disposable caches. No existing caches, environments or data are adopted for deletion.
